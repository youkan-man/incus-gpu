# 状態付きGPUモックによる結合試験

## 実行

リポジトリ直下で次の1コマンドを実行します。sudo、実GPU、実Incusは不要です。

```bash
bash tests/run-gpu-mock.sh
```

Linux/glibc、Bash、Python 3.8以降、Cコンパイラー（ccまたはgcc）が必要です。
`make test-all` では従来の回帰試験も合わせて実行します。

結果は `gpu-mock-results/summary.json` と各ケースのディレクトリに残ります。
ケースごとにCLI標準出力・標準エラー、実行したコマンド、開始前・終了後のPCI/VM状態、
モックの全操作イベント、CLI自身の診断レポートを保存します。
`--output DIR`、`--jobs 1..8`、`--case CASE_NAME` を指定できます。
`--tool PATH` で修正前のCLIを使った対照試験も可能です。

## モックの境界

本番 `incus-gpu` の関数を差し替えず、通常どおりBash CLIを別プロセスで実行します。
補助Python・監視プロセス・変更前記録・復元・排他制御も本番実装のままです。

`io_shim.c` をテスト開始時にビルドし、テスト子プロセスに限って `LD_PRELOAD` します。
一時ディレクトリのsysfsに対する実際のlibc `read/write` をUnixソケットのモックへ渡します。
対象外のファイルI/Oは通常のシステムコールへ転送します。ホストの `/sys` には書き込みません。
`open` 時の `O_TRUNC` を一時sysfsだけで除去し、拒否された書き込みが旧属性値を破壊しないようにします。

独立した `model.py` は、GPU/音声機能のドライバー、`driver_override`、IOMMUグループ、
`/dev/vfio/GROUP` とVFIO cdev、VM設定・状態・模擬ゲストへの割当を保持します。
bind/unbindでdriverシンボリックリンクとVFIOノードを実際に作成・除去します。
CLIの戻り値だけでなく、この状態とイベント順序を照合します。

IncusのCLI境界は `client.py` で同じモデルに接続します。成功文字列を無条件に返す方式ではありません。
VM稼働中のGPU設定追加、使用中グループの解除、誤ったドライバーへのbind等はモデルで拒否します。
模擬起動ではGPU関連機能のVFIO状態・グループを検査してから、模擬ゲストの割当を記録します。

## 再現する構成と障害

基本構成は `0000:0a:00.0 [1002:7590]`、音声機能 `0000:0a:00.1`、IOMMU group 2、
未バインドの `0000:00:03.0 (0x060000)` とPCIeブリッジです。
初期状態を「GPU未バインド・音声のみvfio-pci」とし、ホストドライバー使用状態や音声別グループも試験します。
VM名は `sb-436b44fcd4fe`、プロジェクトは `app-deploy` です。どちらも実ホストではなく模擬状態です。

通常遷移に加え、EINVAL/EBUSY/ENODEV/EIO、属性読み取り停止、override書き込み停止、bind/unbind停止、
関連機能だけの失敗、復元失敗、Incus設定追加・起動・削除失敗、同時操作、使用中グループ/cdev、
CLIタイムアウト後にもサーバー側の起動が続いて後から完了するケースを扱います。
未知のsysfs書き込みは拒否します。障害注入も含めて全要求を記録します。

## 検証できないこと

これは**ユーザー空間の状態モデル**です。実PCIデバイスやGPU命令のエミュレーターではありません。
実Incus/QEMU、実VFIO ioctl、IOMMUのDMA、BARマッピング、GPUファームウェア、PCIe電源・リセット、
AMD固有のカーネル問題、ゲストのGPUドライバー、描画やROCm処理の動作は確認していません。
モックでの「ゲスト割当」はモデル上の検証結果であり、実ゲストの `lspci` 結果ではありません。

停止注入では実際にワーカーのソケット待機を停止させますが、これは通常S状態であり、
実カーネルの割り込み不能なD状態を作るものではありません。終了不能ワーカーの扱いは
従来の別ユニット試験で検証します。実機のD状態やハードウェア停止が解消したとは判定しません。
